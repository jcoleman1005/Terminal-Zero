Alice — when an attack happens, system daemons log events to /var/log/.
Raw logs look dense, but every line follows a strict 4-part anatomy:

  [ TIMESTAMP ]  [ HOST ]  [ DAEMON/SERVICE ]   [ EVENT MESSAGE ]
  03:38:10       apollo    sshd[204]:           Invalid user operator from 192.168.1.105
  └── When       └── Where └── Who logged it    └── What actually happened

--------------------------------------------------------------------------------
1. THE 4 COMMON INCIDENT DAEMONS:
--------------------------------------------------------------------------------
• 'sshd[PID]'   : Secure Shell logins.
                  - "Failed password" = Unauthorized login attempt (brute force).
                  - "Accepted password" = Successful breach / intruder entry.

• 'sudo'        : Administrator privilege escalation.
                  - "COMMAND=..." = Exact command executed with root powers.

• 'kernel'      : Core OS hardware & network events.
                  - "Interface link state degraded: DOWN" = Network port disabled.

• 'systemd[1]'  : System service supervisor.
                  - "code=killed, status=9/KILL" = Service forcefully terminated.

--------------------------------------------------------------------------------
2. YOUR LOG INVESTIGATION TOOLKIT:
--------------------------------------------------------------------------------
• cat <file>            : Stream an entire log from start to finish.
• head -n 5 <file>      : Peek at the earliest events (e.g. system boot).
• tail -n 10 <file>     : Focus on the latest events (e.g. recent attack activity).
• grep -i "pattern" <file>: Filter the noise to find specific keywords or error tags.

--------------------------------------------------------------------------------
3. THE INVESTIGATOR'S MINDSET:
--------------------------------------------------------------------------------
When triaging a compromised machine, ask yourself three core questions:
  1. Entry Point  : How did the intruder get in, and what commands did they run?
  2. Persistence  : Did they spawn any hidden background processes or alter files?
  3. Sabotage     : What network ports or critical services did they take down?

Use your filtering tools to investigate the logs and uncover the trail.
